RuleProof

Rules for AI coding agents — measured, not guessed.

Mines your team's history into rules for IBM Bob, A/B-tests each rule with Bob,
and keeps only the rules that measurably prevent mistakes.

The problem: agents repeat your team's mistakes

  • Coding agents don't know a team's unwritten rules — reviewers catch the same mistakes again and again.
  • The fix today is a rules file (AGENTS.md, .bob/rules) — written by hand or generated with /init. Both are guesswork.
  • Nobody measures which rules change behaviour, and every rule costs tokens on every task.
  • ETH Zurich (AGENTbench, 2026): LLM-generated context files did not improve success but added >20 % cost.

The knowledge that matters is in the history — review comments, reverts, red CI runs. No agent reads it.

How it works

1 · MineCustom Bob IDE mode rule-miner + parallel explore subagents read reviews, git log, CI logs. Only recurring issues, with exact quotes.
2 · VerifyDeterministic checker: every quote must appear verbatim in the sources. Invented evidence is rejected.
3 · TestBob Shell (headless) does the same task on throwaway repo copies, with and without the rule, 3×. Behavioural checks score it.
4 · DecideKEEP only if the pass rate rises. REDUNDANT if Bob already does it. INEFFECTIVE / HARMFUL otherwise.
5 · ShipKEEP rules exported for .bob/rules/. Public dashboard with evidence and Bob's code with/without each rule.

Built with Bob IDE (13 tasks) · measured with Bob Shell (75 A/B runs) · all on the hackathon account

RuleProof3

What a proven rule changes

Task: "Add markDelivered(order) … record the delivery time." Reviewers had flagged the audit convention 3× and CI failed on it.

Bob without rule ✗

function markDelivered(order) {
  if (order.status !== 'shipped') throw …
  return { ...order, status: 'delivered',
           deliveredAt: clock.now() };
}
// no audit.record — check fails
// (other runs: audit.log() → TypeError)

Bob with rule R2 ✓

function markDelivered(order) {
  if (order.status !== 'shipped') throw …
  const updated = { ...order, status: 'delivered',
                    deliveredAt: clock.now() };
  audit.record('order.delivered',
               { orderId: order.id });
  return updated;
}

Rule R2 (mined): "Always call audit.record(eventName, data) — never audit.log(). Data must include orderId; eventName follows 'order.<verb>'." — without 0/3 → with 3/3

Built with Bob, for Bob

How Bob is used

  • Bob IDE Agent mode built every component (13 tasks, screenshots in bob_sessions/)
  • Custom mode rule-miner + parallel explore subagents
  • Bob rule layers .bob/rules as output; /init as baseline
  • Headless Bob Shell as the A/B measurement engine

Why it matters

  • Onboard a repo to Bob with rules that are proven, not guessed
  • Fewer repeated review comments, less rework
  • Small rule files — every rule has earned its tokens
  • Next: CI integration, real-repo A/B, per-mode rule tests
