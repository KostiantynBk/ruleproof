# Project Coding Rules (Non-Obvious Only)

- All internal Fastify instance state must be stored via Symbol keys defined in `lib/symbols.js`. Never create ad-hoc symbols elsewhere.
- `lib/config-validator.js` and `lib/error-serializer.js` are **autogenerated** — editing them directly will be overwritten by `npm run build:validation`. Regenerate with that script after changing the schema in `build/build-validation.js`.
- All errors must be created with `@fastify/error` and registered in `lib/errors.js` with a `FST_ERR_*` code. Do not throw plain `Error` objects from framework internals.
- Deprecation codes `FSTDEP001–FSTDEP025` and warning codes `FSTWRN001–FSTWRN002` are retired; never reuse them.
- Every `.js` source file must start with `'use strict'`. The linter enforces this via `neostandard`.
- Node built-ins **must** use the `node:` prefix (e.g. `require('node:fs')`, `require('node:http')`).
- No trailing commas anywhere — `'comma-dangle': ['error', 'never']` is enforced.
- Max line length is 120 characters (URLs, strings, template literals, regex, and comments are exempt).
- Tests use **Node.js `node:test`** with `t.assert.*` methods. Never use `assert` directly or introduce Jest/Mocha.
- `t.plan(N)` counts must be exact — update them when adding or removing assertions.
- New test helpers belong in `test/helper.js`, not inlined per-test.
- Type-test files live in `test/types/` with `.tst.ts` extension and are run by `tstyche`, not `tsc`.
- Run a single test file via: `node --test test/<filename>.test.js`
