# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Build / Lint / Test Commands

```sh
npm run unit              # run all unit tests (borp)
npm run test:types        # run TypeScript type tests (tstyche)
npm run lint              # eslint only
npm run build:validation  # regenerate lib/config-validator.js and lib/error-serializer.js (autogenerated — do NOT hand-edit)
```

**Single test:** `borp` discovers tests via `.borp.yaml` (only `test/**/*.test.js` and `test/**/*.test.mjs`). Run one file directly:

```sh
node --test test/hooks.test.js
```

Or filter within `borp`:

```sh
node_modules/.bin/borp --pattern 'test/hooks.test.js'
```

## Code Style

- **`'use strict'`** at top of every `.js` file — no exceptions.
- `neostandard` (StandardJS-derived) + no trailing commas (`'comma-dangle': ['error', 'never']`), max line length 120.
- Single quotes, 2-space indent, LF line endings (see `.editorconfig`).
- Node built-ins imported as `require('node:...')` (with `node:` prefix).
- Internal symbols imported from `lib/symbols.js`; use destructured names (e.g. `kReply`, `kHooks`) — never define new ad-hoc symbols outside that file.

## Error / Warning Codes

- All errors created via `@fastify/error` in [`lib/errors.js`](lib/errors.js) — prefix `FST_ERR_*`.
- Deprecation codes `FSTDEP001–FSTDEP025` and warning codes `FSTWRN001–FSTWRN002` are **retired**; never reuse them.
- Warnings created via `process-warning` in [`lib/warnings.js`](lib/warnings.js) — prefix `FSTWRN*` or `FSTSEC*`.

## Architecture Notes

- Entry point: [`fastify.js`](fastify.js). All internal state stored on Symbol keys from `lib/symbols.js`.
- Plugin/encapsulation lifecycle is managed by `avvio` (not Express-style middleware).
- Two auto-generated files — **do not manually edit**:
  - [`lib/config-validator.js`](lib/config-validator.js) — regenerated by `build/build-validation.js`
  - [`lib/error-serializer.js`](lib/error-serializer.js) — regenerated by `build/build-error-serializer.js`
- Type definitions live under [`types/`](types/) and are re-exported via [`fastify.d.ts`](fastify.d.ts).
- Type tests (`test/types/*.tst.ts`) are checked by `tstyche`, not tsc directly.

## Testing Conventions

- Test runner: **Node.js built-in `node:test`** (not Jest/Mocha/tap).
- Assertions use `t.assert.*` (e.g. `t.assert.strictEqual`, `t.assert.ok`) — not `assert` directly.
- `t.plan(N)` is used heavily; always keep plan counts accurate when adding assertions.
- Shared test helpers in [`test/helper.js`](test/helper.js) — use `getServerUrl`, `payloadMethod`, `sleep`, `assertNoWarning`, `partialDeepStrictEqual`.
- `test/internals/` tests individual `lib/` modules in isolation.
- ESM tests live under `test/esm/` as `.mjs` files.
